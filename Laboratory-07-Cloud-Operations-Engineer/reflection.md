# Checkpoint 7: Reflection

### 1. Why check the host's resources even if the containers are running perfectly?

Checking the host's resources is important because containers depend on the host's CPU, memory, and disk space. Even if containers are running properly, limited resources can make applications slow or cause them to stop working. Monitoring the host helps identify problems before they affect the application.

### 2. How would `docker logs` help if a user can't log into a web application?

The `docker logs` command helps me investigate login problems by showing messages generated by the container. These logs may contain errors, failed requests, or connection problems that explain what went wrong. This helps me find clues and troubleshoot the issue instead of guessing.

### 3. What's the difference between monitoring logs and monitoring metrics?

Logs are records of events, errors, and requests that happen inside an application. Metrics are numerical measurements such as CPU usage, memory consumption, and network traffic. Logs help explain what happened, while metrics help me understand the system's performance and identify unusual changes.

### 4. How do large companies monitor thousands of containers?

Large companies use monitoring tools to collect information from many containers automatically. Prometheus collects and stores metrics, while Grafana displays the information through dashboards and graphs. These tools help engineers monitor performance, identify problems, and receive alerts without checking every container manually.

### 5. How has your ability to troubleshoot Linux environments improved?

This laboratory improved my troubleshooting skills because I learned how to check memory, disk space, running processes, Docker logs, and container resource usage. I now understand that finding the cause of a problem requires checking evidence from both the host and the containers. These skills help me identify issues more efficiently.
